Sum query · Accountant report

A transaction sum query behind a report was too slow.

  • A partner had more than 8 lakh rows in accrual transactions, and the query summed them all each time
  • I denormalised it: a job calculates the sum and stores it against each chart-of-accounts entry
  • Behind a key, so only selected customers run this flow
  • Time dropped from around 14–15 minutes to 4–5 minutes, roughly 30% of the original

Join query · Workpaper

A Workpaper query ran for about 10 minutes.

  • A foreign key join was not using its index and ran as if the columns were not indexed
  • The cause: an earlier left join created an intermediate table, so the index was ignored
  • Fix: a forced index, so the values are read from the index
  • Time dropped from about 10 minutes to 1.3 minutes
